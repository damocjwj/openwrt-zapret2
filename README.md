# openwrt-zapret2

[简体中文](README.zh_CN.md)

An unofficial, OpenWrt-native integration of the upstream
[zapret2](https://github.com/bol-van/zapret2) NFQUEUE engine, with a LuCI
management application. Upstream `v1.0.4` is downloaded unchanged and verified
by SHA-256; this repository supplies the OpenWrt packaging and control plane.

## Packages

- `zapret2` `1.0.4-r8`: `nfqws2`, upstream Lua policy files, UCI schema v2,
  ubus API v1, procd integration and the deterministic nftables compiler.
- `luci-app-zapret2` `4.0.0-r31`: settings, ordered Profiles, local lists,
  compact candidate validation, counters and bounded logs.
- `luci-i18n-zapret2-zh-cn` `4.0.0-r31`: Simplified Chinese translation.

The service is disabled by default. The default `marked` interception mode has
an empty include-mark list, so installation alone does not capture traffic.

## Install from a feed

Add the repository to `feeds.conf.default`:

```text
src-git zapret2 https://github.com/damocjwj/openwrt-zapret2.git
```

Then install and select the packages:

```sh
./scripts/feeds update zapret2
./scripts/feeds install -p zapret2 zapret2 luci-app-zapret2
make menuconfig
```

Select `Network -> Firewall -> zapret2` and `LuCI -> Applications ->
luci-app-zapret2`. The translation package is generated by the LuCI build
system when the corresponding language is selected.

This package targets firewall4/nftables systems. It requires NFQUEUE kernel
support and rejects standard software or hardware flow offload because bypassed
flows cannot be processed reliably.

## Configuration model

Traffic passes through two independent layers:

1. The OpenWrt interception layer selects WANs, forwarded or router-local
   traffic, address families and packet marks. Exclude marks always take
   precedence. `all` mode is available, but may also include proxy or VPN
   tunnels unless they are excluded by an external mark.
2. Enabled Profiles are evaluated in order by `nfqws2`; the first matching
   Profile wins. Payload and range steps affect only actions that follow them
   in the same Profile.

The default configuration provides conservative HTTP and TLS Profiles and a
disabled QUIC Profile. They are examples, not universal DPI-bypass settings.
Choose strategies appropriate for the network being used.

`queue_mode` is enforced by nftables before Profile matching. Overlapping TCP
or UDP ports must use the same queue mode; mixing `initial` and `keepalive` on
overlapping ranges is rejected.

The optional [Nikki marked-traffic example](examples/nikki-marked-direct.yaml)
shows how an external policy engine can provide a generic packet mark. Zapret2
does not recognize Nikki, Mihomo, `DIRECT` or any other application-specific
policy name.

## LuCI workflow

The four pages separate runtime settings, ordered Profiles, local lists and
recent logs. Editing a Profile or step changes only the browser-side candidate
until it is saved.

The Profiles page can validate the current candidate without saving it. The
compact validation row distinguishes unvalidated, validating, valid, valid with
warnings and invalid states. `Save` validates before writing UCI; `Save & Apply`
validates, commits the configuration and reloads Zapret2. All three paths use
the same compiler as service startup.

## Upgrade and safety notes

- API v1 requires UCI schema v2. Earlier experimental wrapper schemas are not
  interpreted automatically; back them up and recreate the configuration.
- Reserve `connection_mark`, `generated_mark`, the NFQUEUE number and external
  include/exclude marks so they do not overlap other firewall components.
- Zapret2 manages only `/var/run/zapret2`, its validated list directories and
  `inet zapret2`. Stopping it does not rewrite firewall4, routes or proxies.
- Invalid reloads preserve the last running process and rules. Applied-state
  commit failures roll back the nftables table and runtime metadata.

## Diagnostics

Validate the saved configuration without starting the service:

```sh
/etc/init.d/zapret2 validate
```

Query the versioned API:

```sh
ubus call zapret2 status '{"api_version":1,"schema_version":2}'
ubus call zapret2 validate '{"api_version":1,"schema_version":2}'
logread -e zapret2
```

Common startup failures are missing include marks in enabled `marked` mode,
overlapping reserved marks, unresolved WAN/source networks, conflicting queue
usage, overlapping queue modes, invalid list entries and enabled flow offload.

## Development

```sh
sh zapret2/tests/test-contract.sh

for file in luci-app-zapret2/htdocs/luci-static/resources/zapret2/v4r31/*.js \
            luci-app-zapret2/htdocs/luci-static/resources/view/zapret2/v4r31/*.js; do
    node --check "$file"
done

node luci-app-zapret2/tests/test-ui.js
msgfmt --check --check-format -o /dev/null \
    luci-app-zapret2/po/zh_Hans/zapret2.po
msgcmp luci-app-zapret2/po/zh_Hans/zapret2.po \
    luci-app-zapret2/po/templates/zapret2.pot
```

CI repeats these checks and builds all three packages with a SHA-256-pinned
OpenWrt 24.10.4 MediaTek/Filogic SDK. `libcap` is a build-only dependency;
the resulting `nfqws2` does not link `libcap.so`.

See [Architecture and interfaces](docs/architecture.md) for the API, compiler
and security boundaries. Device tests under `zapret2/tests/` are opt-in and may
temporarily alter Zapret2 or external policy-engine runtime state.

## Deliberate exclusions

`zapret2-tools`, blockcheck, remote list downloads, arbitrary scripts, argv,
Lua, paths, blobs and raw nftables input are intentionally not exposed.
